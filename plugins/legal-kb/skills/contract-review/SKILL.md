# 계약서 검토 (legal-kb)

> 구조는 Anthropic [claude-for-legal](https://github.com/anthropics/claude-for-legal) `commercial-legal` 플러그인의
> `review`·`vendor-agreement-review`·`cold-start-interview` 스킬(Apache License 2.0)을 참고했다 —
> 제목으로 종류 판별 → 조직 기준(playbook) 대조 → 조항별 판정 → 수정 문구 → 메모, 인용 출처 표시.
> 판정 기준·근거·문구는 한국 법(근로기준법·주택임대차보호법·하도급법·약관법·민법 등)으로 새로 썼다.

**판정은 서버의 `contract_review` 도구가 한다. 이 스킬을 읽는 모델은 판정하지 않는다.**
도구는 계약서를 조항(제N조·특약N·별지N)으로 나누고, 계약 종류별 검토 기준표의 규칙으로 색을 정하고,
색마다 근거(「법령명」 제N조·판례 사건번호)와 수정 예시를 기준표에서 그대로 붙인다.
모델이 자기 지식으로 판정하면 노랑을 빨강으로 올리고 정상 조항을 문제 삼는 경우가 많았다
(기준선: 정밀도 0.73·노랑→빨강 과잉 0.75~0.80·정상본 오탐 2.17건/건 → 도구 판정 0.925·0.40·0.33, RAG-9728).

## 흐름

```
1. 계약서 원문 확보 ─ 파일이면 Read, 붙여 넣은 글이면 그대로
2. 종류·의뢰인 판별 ─ 제목·별지 제목 먼저
3. (선택) 조직 기준 확인 ─ 설정 파일 또는 인터뷰
4. contract_review(text, type, client, as_of)   ← 판정. 반드시 먼저, 한 번
5. 근거 확인 ─ 인용할 빨강 근거만 get_article / get_decision
6. 조직 기준 덧씌우기 ─ 노랑↔초록만
7. 판정표 · 수정 문구 · 빠진 조항 · 메모
```

### 1. 계약서 원문

- `text` 에는 **원문 전체를 그대로** 넣는다(제목·당사자·전문·조항·특약·서명란, 6만 자까지). 요약하거나 조항을 골라 넣지 않는다 — 분할·종류 판별·빠진 조항 탐지가 전문을 본다.
- PDF·DOCX·HWP 파일이면 Read 로 글을 뽑아 넣는다. 스캔본처럼 글이 없으면 그렇다고 말하고 글을 받는다.
- 계약서가 없으면 달라고 한다. 조항 몇 개만 받았으면 그 범위만 검토한다고 밝힌다.

### 2. 종류와 의뢰인

본문 낱말보다 **제목과 별지 제목**을 먼저 본다(비밀유지 낱말이 많은 용역계약서는 비밀유지계약서가 아니다).

| 제목에 있는 말 | `type` |
|---|---|
| 근로계약서·연봉계약서·단시간근로자 근로계약서 | `labor` |
| 주택임대차계약서·전세계약서·월세계약서 | `lease_house` |
| 용역계약서·업무위탁계약서·도급계약서·하도급계약서·개발계약서 | `service` |

- 확실하면 `type` 을 넘기고, 애매하면 비워 둔다 — 도구가 판별하고, 못 하면 `need_type` 오류를 돌려준다. 그때 위 표로 정해 다시 부른다.
- **표에 없는 계약**(상가 임대차·매매·투자·주주간·라이선스·비밀유지 단독 계약 등)은 도구가 다루지 않는다. 도구를 억지로 부르지 말고 "검토 기준표 밖 계약이라 모델 검토"라고 먼저 밝힌 뒤 legal-research 스킬 흐름(research → get_article)으로 쟁점 조항을 확인한다. 이때 판정 근거는 조회한 조문·판례로만 단다.
- `client` 는 누구 편에서 보느냐다: 근로자·사용자 / 임차인·임대인 / 수급사업자·원사업자·발주자·수행사. 질문에 있으면 그대로 넘기고, 없으면 넘기지 않는다(기준표의 기본 관점으로 본다). 관점이 결론을 바꾸는 조항(위약금·지체상금·해지권)이 있으면 메모에 "의뢰인 미지정"을 적는다.
- `as_of` 는 질문에 기준일이 있을 때만(최저임금 판·법령 판이 바뀐다). 없으면 오늘.

### 3. 조직 기준 (선택)

조직(로펌·회사)마다 받아들이는 조건이 다르다 — 지체상금 상한, 대금 지급기일, 비밀유지 기간, 관할 법원 같은 **협상 자리**. 이것을 기준으로 노랑·초록을 다시 볼 수 있다.

- `~/.claude/plugins/config/legal-kb/contract-playbook.md` 가 있으면 읽는다.
- 없고, 사용자가 "우리 기준으로", "조직 기준 설정", "플레이북" 을 말하면 [`references/org-playbook.md`](references/org-playbook.md) 의 인터뷰를 한다(빠른 5문항). 답을 그 파일에 저장해도 되는지 묻고 저장한다.
- **사용자가 요청하지 않았거나 대화형이 아니면(한 번에 답해야 하는 요청) 묻지 않는다.** 기본 기준표로 진행하고 메모 머리에 "조직 기준 없음 — 기본 기준표 적용"을 적는다.

### 4. `contract_review` — 먼저, 한 번

```
contract_review(text=<원문>, type="labor"|"lease_house"|"service", client="근로자", as_of="YYYY-MM-DD")
```

- `research`·`search_legal` 을 먼저 부르지 않는다. 계약서 검토의 1단계는 이 도구다.
- 기본 `detail=summary` 로 충분하다(조항별 색·이유·근거·수정 문구, 빠진 조항, 최저임금 계산 결과 `calc`). 사용자가 상세 메모(판시 구절·표준계약서 원문·계산 과정)를 원할 때만 `detail="full"`.
- 결과의 `counts`·`clauses[].color`·`missing[]` 이 판정이다. `warnings` 가 있으면 메모에 옮긴다.
- 도구가 목록에 없거나 `unavailable` 이면: "검토 모듈을 쓸 수 없어 모델이 직접 검토했다"고 먼저 밝히고, 2단계의 기준표 밖 계약처럼 조회한 조문으로만 근거를 단다.

### 5. 근거 확인 — 필요한 것만

도구가 준 `basis` 는 기준표가 KB 조문 문구로 검증해 둔 근거라 그대로 인용해도 된다. 원문을 더 읽는 것은 다음일 때만이다(합쳐 3~5회 안).

- 빨강 조항의 근거 조문을 **항·호·단서까지** 인용해야 한다 → `get_article(law_name, article_no, as_of)`
- 근거가 판례 사건번호이고 판시 내용을 적어야 한다 → `get_decision(case_no)`
- `standard`(대응 표준계약서 조항)와 문구를 나란히 보여 줘야 한다 → `get_article(<표준계약서 이름>, <조 번호>)`

노랑·초록 조항을 위해 조문을 다시 읽지 않는다. 호출자 토큰이 비싸다.

### 6. 판정을 바꿀 수 있는 경우

도구의 색을 그대로 쓰는 것이 원칙이다. 바꿀 수 있는 것은 아래 둘뿐이고, 바꾸면 표에 바꾼 이유를 적는다.

| 경우 | 허용 | 표기 |
|---|---|---|
| 조직 기준이 그 조건을 받아들인다/거절한다 | 노랑→초록, 초록→노랑 | `조직 기준: <항목>` |
| 도구가 초록으로 본 조항에 **강행규정 위반**이 보인다 | 초록·노랑→빨강. 단 `get_article` 로 그 조문을 읽고 문구를 확인한 뒤에만 | `검토자 상향(도구: green)` + 확인한 조문 |

- **빨강은 낮추지 않는다.** 조직 기준·의뢰인 사정으로도 강행규정 위반·무효 판정은 바꿀 수 없다. 조직이 감수하겠다는 빨강은 "위험 감수 결정 필요"로 올려 둔다.
- 노랑을 빨강으로 올리지 않는다(위 둘째 줄의 확인 절차를 거친 경우 말고). 기준선에서 가장 많이 틀린 자리다.

### 7. 출력

사용자가 다른 형식(JSON·표만·한 줄 요약)을 요구하면 그 형식을 따르되, 색·근거는 도구 결과(와 6절의 바꾼 내역) 그대로 옮긴다. 조항 번호는 도구의 `clause`(제N조·특약N·별지N) 그대로 쓴다.
요구가 없으면 아래 메모를 쓴다.

```markdown
> 전문가 검토용 초안 — 법률 자문이 아닙니다. (도구 disclaimer 문장)

# 계약서 검토: <계약 종류> (<의뢰인> 관점)

**기준일** YYYY-MM-DD · **기준표** <playbook> · **조직 기준** 없음 — 기본 기준표 적용 | <파일> 적용

## 결론
<서명 전 반드시 고칠 것 한두 줄. 빨강 n · 노랑 n · 초록 n>

## 조항별 판정
| 조항 | 판정 | 이유 | 근거 | 수정 문구 |
|---|---|---|---|---|
| 제N조(제목) | 🔴 red | ... | 「법령명」 제N조 | ... |
| 제N조(제목) | 🟡 yellow | ... | 「법령명」 제N조 | ... |
| 제1조~제4조 | 🟢 green | 문제 없음 | | |

## 빨강 조항 상세
<조항별: 문제 문구 → 왜 무효·위반인지(근거 원문 한 구절) → 수정 문구 전문>

## 빠진 조항
| 항목 | 판정 | 근거 | 넣을 문구 |

## 확인할 것
<도구 warnings, 하도급법 적용 여부·약관 해당 여부 같은 사실 확인, 의뢰인 미지정, 6절 바꾼 내역>

## 다음 단계
수정본(수정 문구 반영 전문) 작성 / 상대방에게 보낼 요청 목록 / 검토 메모 DOCX(웹 사건 화면 '계약 검토'에서 내려받기)
```

- 초록 조항은 묶어서 한 줄로 쓴다. 표가 길어지면 노랑·빨강만 행으로 쓴다.
- 금액(최저임금·지연이자) 판정은 도구의 `calc` 문장을 옮긴다. 직접 계산하지 않는다 — 더 계산할 것이 있으면 legal-research 스킬의 `calculate` 절을 따른다.

## 인용

- 조문: 「법령명」 제N조 제M항 (기준일 또는 시행일). 도구 `basis` 의 "법령명 제N조" 를 이 형식으로 옮긴다. 시행령은 본법과 구분해 「하도급거래 공정화에 관한 법률 시행령」 제3조처럼 쓴다("같은 법 시행령" 금지).
- 법령명은 **정식 명칭**으로 쓴다. 근거 칸·괄호 인용에서 약칭(하도급법·약관법·주임법)이나 "법 제N조" 를 쓰지 않는다 — 검토자가 그대로 `get_article` 로 찾을 수 있어야 한다. 본문 문장은 처음에 「하도급거래 공정화에 관한 법률」(이하 하도급법)처럼 밝힌 뒤 약칭을 써도 된다.
- 판례: 법원 + 선고일 + 사건번호. 선고일을 모르면 `get_decision` 으로 확인하고, 확인하지 않았으면 사건번호만 쓴다.
- 표준계약서: 「<표준계약서 이름>」 제N조 (공정거래위원회·고용노동부 등 제정 기관).
- **도구 결과나 `get_article`·`get_decision` 으로 확인하지 않은 조문·사건번호는 인용하지 않는다.** 꼭 필요하면 `[모델 지식 — 확인 필요]` 를 붙이고 판정 근거로는 쓰지 않는다.

## 하지 않을 것

- `contract_review` 를 부르지 않고 자기 지식으로 조항 색을 매기기 (기준표 계약 3종에서)
- 계약서를 요약하거나 일부만 `text` 에 넣기
- 빨강을 조직 기준으로 낮추기, 확인 없이 노랑을 빨강으로 올리기
- 도구가 준 근거를 다른 조문 번호로 바꾸거나 근거를 지어내기
- 계약서 검토 중 `web_search` (기준표·조문으로 닫히지 않는 사실만 legal-research 규칙대로)
- "전문가 검토용 초안" 표기 빼기
